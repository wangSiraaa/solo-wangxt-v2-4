# 🔭 NightPlan — 观测提案到可执行夜间计划

天文台夜间观测排程系统：申请人录入目标坐标、曝光时长与滤镜；值班科学家选定观测夜后，
系统用 FastAPI + Astropy 计算哪些目标因**高度角、月距或天文晨昏窗口**不可执行，
并生成带**设备准备、滤镜切换**开销的夜间时间轴。录入本地天气样本后，
系统**只重排尚未开始的曝光**，**已采集帧不会再次占用申请额度**；
人工调整必须填写原因，且每次变化都保留为**不可变计划版本**。

不连接真实望远镜，全部以本地数据演示中断 → 重排 → 观测完成。

## 架构

```
frontend/   React + Vite：提案录入、夜间时间轴、可行性解释表、
            版本切换、天气模拟、人工锁定、已采集帧台账
backend/    FastAPI
  app/astronomy.py   Astropy：太阳高度（-18° 天文晨昏）、目标 Alt/Az、月角距
  app/scheduler.py   2 分钟网格贪心排程（准备 10min / 滤镜切换 3min / 读出）
  app/service.py     计划版本管理、中断标记、已采集帧入账、版本差异
  app/models.py      PostgreSQL（提案/目标/夜/版本/块/帧台账/人工调整）
  app/seed.py        演示数据（兴隆站，2026-09-18，6 个目标）
  app/demo.py        命令行完整剧本
PostgreSQL  15（无 root 时由脚本从 Debian 包装到 ~/opt）
```

## 快速开始

### 一键命令行演示（中断、重排、完成）

```bash
bash scripts/demo.sh
```

输出 3 个计划版本：

| 版本 | 触发 | 内容 |
|---|---|---|
| v1 | initial | 初始计划：4 个可行目标排满 14 帧；ω Cen 因高度角、Sgr 候选因月距被拒并给出解释 |
| v2 | weather | 14:04 UTC 起中层云：跨点的 NGC 891 #1 标记**中断（不计额度）**，之前 8 帧入账，之后的曝光顺延重排 |
| v3 | manual | 值班科学家把 M45 #3 锁定到 16:00–16:06（与标定同步），**原因随版本保存** |

夜结束打印已采集帧台账（14 帧，帧号唯一、重排不重复计数）。

### Web 界面

```bash
# 终端 1：数据库 + API
bash scripts/setup-postgres.sh
cd backend
.venv/bin/uvicorn app.main:app --reload --port 8000   # 或 python -m app.seed 重置演示数据

# 终端 2：前端
cd frontend && npm install && npm run dev
# 打开 http://127.0.0.1:5173  （/api 代理到 8000）
```

界面操作顺序：

1. **生成初始夜间计划** → 时间轴显示黑夜底、目标可见区间、准备/切换/曝光块；
   下方表格逐目标说明不可执行 / 未排满的原因。
2. **☁ 本地天气样本** → 填中断/恢复时刻（预填 14:04–15:20 UTC），点击「中断并重排」。
3. **✋ 人工锁定** → 选目标帧号、时段，填原因后「锁定并重排」。
4. **▶ 推进执行** → 登记此前已结束的帧，查看帧台账，最后「结束观测夜」。
5. 顶部 **v1/v2/v3 标签页**对比各版本块的搬移；「与上一版差异」给出搬移/保持计数。

时间轴图例：深色带=天文黑夜，蓝虚线框=该目标可见区间（高度+月距），红色斜纹=天气；
实心=已完成（绿框），虚线=计划，红斜杠块=中断且不计额度。

## 关键业务规则

- **可行性**（`astronomy.assess_target`）：科学曝光网格点必须同时满足
  太阳 < −18°、目标高度 ≥ 目标阈值（默认 30°）、月角距 ≥ 阈值（默认 40°）。
  不满足时给出具体数值原因（如"整夜高度角低于 30°（最高 2.0°）"）。
- **准备与滤镜切换**：每目标首次观测前 10 分钟寻星/导星；当前光路滤镜与目标不同则
  3 分钟切换。同滤镜相邻目标不重复切换。
- **贪心排程**：每一步为所有有剩余额度的目标计算"下一帧最早完成位置"，
  取最早者（优先级次之），因此高优先级目标不会无意义地霸占升起前的时间。
- **天气重排**：跨中断点的进行中块置 `interrupted`（曝光未完成）；
  只对 `as_of` 之后的部分重新排程；`acquired_frames` 有 `(夜, 目标, 帧号)` 唯一约束，
  已入账帧永远只扣一次申请额度。
- **人工调整**：`pin`（锁定某目标某帧到指定时段）与 `hold`（封锁时段），
  原因强制非空，写入 `overrides` 审计表，并生成 `manual` 计划版本。
- **版本不可变**：每次初始/天气/人工动作都新建 `plan_versions` + `plan_blocks` 快照，
  旧版本保留状态与原因，可随时回看。

## API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/proposals`, `/proposals/{id}/targets` | 提案、目标录入（坐标/曝光/滤镜/帧数） |
| POST | `/nights` | 值班科学家选定站点本地观测夜 |
| POST | `/nights/{id}/plan` | 生成 v1 初始计划（含可行性解释） |
| GET | `/nights/{id}/timeline` | 全部版本时间轴 + 黑夜窗口 + 天气 + 帧台账 |
| POST | `/nights/{id}/simulate-weather` | 天气样本：登记完成帧、中断跨点块、重排 |
| POST | `/nights/{id}/overrides` | 人工 pin/hold（原因必填），生成 manual 版本 |
| POST | `/nights/{id}/complete`, `/finish` | 推进执行、结束观测夜 |

交互式文档：`http://127.0.0.1:8000/docs`。

## 说明

- 时间轴与接口时间均为 **UTC**（演示站点兴隆为 UTC+8）。
- Astropy 使用离线内置表，运行时不需要联网。
- 无 Docker/root 环境：`scripts/setup-postgres.sh` 用 `apt-get download` + `dpkg-deb -x`
  把 PostgreSQL 15 装到用户目录，unix socket 监听 `~/opt/pgdata:55432`；
  有正常 PostgreSQL 时直接设置 `DATABASE_URL` 即可覆盖。
